# 日本のインボイス制度チェック（`jp-invoice-check`）

請求書・領収書がインボイス（適格請求書・適格簡易請求書）の要件を満たすかを見て、不足箇所と直し方を示します。税率ごとの消費税額の検算と、登録番号（T＋13桁）の形式・法人番号の検査桁の確認もできます。

> 無料（MIT） ・ v1.0.0 ・ 作者: frametech

## こう頼むと動きます

- 「この請求書の記載がインボイスの要件を満たしているか見て」
- 「税率ごとの消費税を計算して」
- 「登録番号 T1234567890123 は形式として正しい？」
- 「領収書をインボイスにするには何が足りない？」
- 「10%と8%が混在する請求書の消費税額の出し方」

## 何が違うか

出力は「該当要件・状況・直し方」の表と、計算結果、末尾の「要確認」の一覧です。端数処理は**1枚の請求書につき税率ごとに1回**（品目ごとに端数処理した合計は認めない）で計算し、記載された税額との差も照合します。時限措置（仕入税額控除の経過措置の割合など）は改正が続いているため、確認日つきで `references/transitional.md` に置き、最新は国税庁で確認するよう案内します。個別の税務判断は断定しません。

評価（2026-10-22、Claude Code のサブエージェント／sonnet で各3回。比較対象はスキルなし・Web 検索あり）: タスク達成 94%（スキルなし 93%）／ 発火の模擬判定 発火すべき依頼 11/11・すべきでない依頼 12/12（2回）

**差は小さいスキルです。** インボイス制度は国税庁の公開情報が中心なので、Web 検索が使える環境ではスキルなしでもほぼ同じ結果になりました。差が出たのは、簡易インボイスで宛名を省略できること、経過措置の70%での計算など一部の項目だけです。一方でスキル側にも、登録の有無を公表サイトで照会するよう案内する項目が抜けた回がありました。このスキルの利点は、検索しなくても要件・端数処理・登録番号の検査桁の手順が手元に揃っていることと、スクリプトで検算できることです。

Agent Skills 形式（`SKILL.md`）のスキルです。対応しているエージェント（Claude Code・Codex・Cursor・Gemini CLI・GitHub Copilot・OpenCode・Kimi Code ほか79種、2026-10-07 時点）ではフォルダのまま使えます。

| 使い方 | 実機で確認した環境・モデル | 確認日 |
|---|---|---|
| エージェントに入れる | Claude Code ／ sonnet（サブエージェント） | 2026-10-22 |
| チャット・API に貼る | 未確認 | — |

上の表にない環境は、Agent Skills 形式に準拠していますが未検証です。

必要なもの: 追加で必要なものはありません。`scripts/invoice.py` は Python 3.9 以上（標準ライブラリだけ）で動きます。無くても `references/` の式で手計算して進められます。

既知の制限:
- 個別の税務判断・仕訳・申告書の作成は対象外です
- 登録の有無は国税庁の公表サイトでの照会が必要です（スクリプトは通信しません）
- 個人事業者の登録番号の検査桁は公開仕様を確認できず、形式のみ確認します
- 時限措置は 2026-10-22 の確認時点。90日を過ぎたら公式を読み直してください
- 消費税法・施行令の条文本文は e-Gov が取得できず、条文番号は国税庁タックスアンサーの根拠法令欄によります

## インストール

**エージェントにまとめて入れる**（入っているエージェントを自動で見つけます）

```bash
npx skills add frametech971-png/skills --skill jp-invoice-check        # このプロジェクトだけ
npx skills add frametech971-png/skills --skill jp-invoice-check -g     # すべてのプロジェクトで
```

**Claude Code のプラグインとして**

```
/plugin marketplace add frametech971-png/skills
/plugin install jp-invoice-check@frametech-skills
```

**手で置く**: このフォルダごと、Claude Code はプロジェクトの `.claude/skills/jp-invoice-check/`、Codex・Cursor・Gemini CLI・GitHub Copilot・OpenCode・Kimi Code などはプロジェクトの `.agents/skills/jp-invoice-check/` に置く。claude.ai はフォルダを zip にしてアップロードする。

**チャット・API で使う（ChatGPT・Gemini・Grok・DeepSeek など）**: `prompts/jp-invoice-check.prompt.md` を、プロジェクト・Gem・GPT の知識ファイルとして入れるか、会話の最初に貼ってから「このスキルで〜して」と頼む。API ではシステムプロンプトに入れる。`npx skills use frametech971-png/skills@jp-invoice-check` でも同じプロンプトが出ます。

## このスキルが実行すること

- `scripts/invoice.py`: `regno` は登録番号の形式と法人番号としての検査桁を確認し、`tax` は税率ごとに合計して消費税額等を1回だけ端数処理します。引数で受け取った値を計算するだけで、ファイルは読み書きせず、外部への通信もありません。
