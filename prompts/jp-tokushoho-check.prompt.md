# 特定商取引法表記（通信販売）の点検

目的: 通信販売の「特定商取引法に基づく表記」と、申込みの最終確認画面を、特定商取引法（以下「法」）と同法施行規則（以下「規則」）に照らして点検し、抜けを根拠条文つきで指摘する。下書きも作る。
入力: 表記の本文（点検のとき）、最終確認画面の文言（あれば）、事業の実態の聞き取り（個人か法人か、何を売るか、価格・支払・提供時期、返品・解約の方針）。
出力: 「項目 / 該当条文 / 現状の記載 / 指摘 / 直し方」の表と、末尾の「要確認」一覧。ひな形のときは `【要入力】` つきの下書き。
法的な結論は断定しない。根拠条文と、記載が見当たらない箇所を示すところまでが役目。

## 1. 条文の確認日（先に読む）

条文と運用は `references/` に確認日つきで置いてある。**確認日（2026-10-23）から90日を過ぎたら、公式を読み直してから使う。** 公式の入口:

- 消費者庁 特定商取引法ガイド（通信販売）https://www.no-trouble.caa.go.jp/what/mailorder/
- 同 通信販売広告Q&A https://www.no-trouble.caa.go.jp/qa/advertising.html
- e-Gov 法令検索 特定商取引に関する法律 https://laws.e-gov.go.jp/law/351AC0000000057 ／ 同施行規則 https://laws.e-gov.go.jp/law/351M50000400089
- 消費者庁 ガイドライン・通達 https://www.caa.go.jp/policies/policy/consumer_transaction/specified_commercial_transactions/

**条番号は古い解説とずれる。** 事業者情報などの表示事項は法11条6号に基づく**規則23条**、表示方法は**規則24条**、省略は**規則25条**、返品特約を最終確認画面に表示する方法は**規則44条**（旧い解説の規則9条・16条の2は現行の番号ではない）。引用された条番号は現行と照らす（`references/articles.md`）。

## 2. 最初に聞くこと（1回にまとめて）

素材に無いものだけ聞く。聞けない場合は、仮置きせず「要確認」か `【要入力】` に回す。

1. 事業者: 個人か法人か。氏名（戸籍上）または名称（登記上）、住所、電話番号、法人なら代表者か通信販売業務の責任者
2. 売るもの: 物、ダウンロード、会員制サービス、サブスク、オンライン講座など。1回きりか、継続課金か
3. 価格: 税込、送料、手数料などの追加負担。初回無料・割引から通常価格に移るか
4. 支払の時期と方法、提供の時期（購入直後に使えるか、入金確認後か）
5. 返品・返金・解約の方針（可否、期間、条件、費用負担、方法、期限、違約金）
6. 申込み画面: 最終確認画面があるか、ボタンの文言、そこに何を表示しているか。プラットフォーム（BASE・STORES など）経由か自社サイトか
7. 住所・電話番号を出したくない事情があるか（自宅、バーチャルオフィス、プラットフォーム）
8. 外国の事業者か、国内に事務所があるか

## 3. 点検モード

1. 表記の本文を読む。文字にできるなら `python3 scripts/tokusho_scan.py <本文のファイル>` を実行し、キーワードの有無・取り残しの記号・古い条番号を一覧にする（実行できない環境では `references/checklist.md` を見ながら手で確かめる）。**スクリプトの「検出」は言葉があるだけで、適否の判断ではない。**
2. `references/checklist.md` の T01〜T22 を順に当てる。条文の中身は `references/articles.md`。
3. 表で返す。1行は1項目。

```
| 項目 | 該当条文 | 現状の記載 | 指摘 | 直し方 |
|---|---|---|---|---|
| 引渡時期 | 法11条3号・規則24条2号 | 「入金確認後に発送」 | 期間または期限で示されていない可能性があります（「入金確認後、直ちに」なら表示ありと扱われる旨が消費者庁Q&Aにあります） | 「ご入金確認後、直ちにダウンロードできます」のように期間・期限で書く |
```

- 「現状の記載」は本文の引用か、「記載が見当たりません」。創作しない
- 指摘は「〜の可能性があります」「記載が見当たりません」「事実を確認のうえ判断してください」。「違法です」「違反しています」と書かない
- 重さは「要対応の可能性／要確認／推奨」で分ける。法11条の表示事項の欠落、最終確認画面（法12条の6）の表示事項の欠落、返品・解約に関する事項の欠落は上に置く
- 表記ページに書いただけでは、最終確認画面の義務（法12条の6第1項）を果たしたことにならない。最終確認画面に表示するか、そこから明確にリンクして参照先に明記する（`references/digital-subscription.md`）

## 4. 通信販売に当たるか・物か役務か

- ネットで申込みを受ける販売は通信販売。ランディングページなど申込みを受ける広告にも法11条の表示事項が要る（消費者庁Q&A）
- 有償の情報配信サービスは「役務」で、商品の販売がなくても規制対象（同Q&A）
- 法15条の3（引渡しから8日以内の撤回・解除）は商品と特定権利の話で、返品が観念できない役務は対象外（通達）。**ダウンロード型を商品として扱うか役務として扱うかは、一次情報で断定できていない。** 規則23条6号はダウンロード・配信型を「役務」の書きぶりで動作環境の表示対象にしている。結論は出さず「要確認」にし、どちらでも**法11条5号の「撤回又は解除に関する事項」は表示が要る**ことを示す
- 訪問して契約する、電話で勧誘するなど別の販売形態は対象外（通信販売の節の外）

## 5. デジタル商品・サブスクで必ず見る点

詳細は `references/digital-subscription.md`。

- 提供時期: 「直ちに」「即時」は表示として認められる。「入荷次第」「入金確認後発送」だけは不可
- 動作環境: ソフトウェア・配信・ダウンロードでは、使うのに必要な環境（規則23条6号）
- 継続課金: 2回以上続く契約はその旨、金額、契約期間などの販売条件（規則23条7号。省略不可）。最終確認画面には各回の代金、総額（または目安）、支払時期、引渡時期、解約の方法・期限・違約金
- 無料期間から有料へ自動で移る場合は、移る時期と金額を事前に明確に
- 解約方法を限定する（電話のみ、特定の時間帯のみ、追加の個人情報が要る等）なら、広告と最終確認画面にも明確に表示する。表示しても、その制限が民事上有効になるとは限らない（消費者契約法等）
- 電話で解約を受けるなら、確実につながる番号を、解約用だと分かる形で

## 6. 返品不可と書きたいとき

1. 法15条の3: 特約が無いと、商品は引渡しから8日以内に（送料は購入者負担で）返品できる。返品特約を**広告に表示**していれば特約が優先され、インターネット通販では**最終確認画面にも**表示が要る（規則44条）
2. 書く内容は「可否」「条件・期間」「返品の費用負担」。重要な3点は他より明瞭に（商品の価格に近い位置、同じ大きさ、色・太字）。「その都度ご相談」は返品特約の表示にならない（Q&A）
3. 品質に問題のない商品の返品を認めない場合も、その旨を書く。「欠陥がある場合を除き返品に応じません」のように、**契約内容に適合しない場合の責任**（規則23条5号）と区別して書く（通達・ガイドライン）
4. 返品特約は広告の省略対象にならない（規則25条）
5. 「返品不可」と書いても、消費者契約法などで無効になる条項があり得る。書けば全部有効になるとは言わない

## 7. 氏名・住所・電話番号の省略と非公開

詳細は `references/omission.md`。

- 原則は表示。個人事業者も氏名が要り、屋号やサイト名だけは不可。住所は現に活動している場所で、私書箱は住所にならない
- 省略できるのは法11条ただし書の場合だけ: 広告に「請求により、書面または電磁的記録を遅滞なく提供する」旨を表示し、**実際に請求があれば遅滞なく提供できる措置**を講じていること。「遅滞なく」は、申込みの意思決定に先立って十分な時間的余裕をもって、という意味
- 省略は「匿名で売れる」ではない。請求があれば開示する。開示できる体制（連絡の受け口、応答の期限、開示する情報）を先に決めてあるかを確認する
- 個人事業者がプラットフォームやバーチャルオフィスの住所・電話番号で代える場合は、消費者庁Q&Aの要件（取引がそのプラットフォーム上であること、合意、本人が実際の住所と本人名義の電話番号を把握し確実に連絡できること）を満たすか事実を確認する。満たすかは断定しない

## 8. ひな形モード

`references/template.md` をもとに、聞き取った事実だけで下書きを作る。

- 空欄は `【要入力】`（＜＞や○○にしない）。聞いていない事実（住所、電話、価格、送料、期間、返品条件）は入れない
- 事実が無いと確認できていない節は消さず `【要確認】` を残す
- 最後に「事実を確認し、公開前に専門家の確認を受けることを勧める」と一言添える
- 下書きにも `python3 scripts/tokusho_scan.py <ファイル>` で取り残しを確認できる

## 9. 返し方

1. 点検表（または下書き）
2. 最終確認画面について確認が要る点（該当するときだけ）
3. 要確認の一覧（項目: 理由）
4. 根拠の確認日と、最新は公式で確認する旨（URL）

## 10. 対象外

個別の法的助言（罰則の見通し、訴訟・行政対応、契約の有効性の結論）、特定電子メール法・メール配信の同意の取り方、景品表示法（二重価格・No.1表示など）、個人情報の取扱いやプライバシーポリシー、訪問販売・電話勧誘販売など通信販売以外、日本以外の法域。依頼されたら対象外と伝え、必要なら専門家への相談を勧める。

## 法（通信販売の節）

| 条 | 内容（要約） |
|---|---|
| 2条 | 通信販売の定義 |
| 11条 | 広告の表示事項。1号 販売価格（送料が別なら送料も）、2号 代金の支払の時期と方法、3号 引渡時期・提供時期、4号 申込みの期間に関する定めがあるときはその旨と内容、5号 申込みの撤回又は解除に関する事項（15条の3第1項ただし書の特約があればその内容を含む）、6号 そのほか主務省令（規則23条）で定める事項。**ただし書**: 広告に、請求により事項を記載した書面を遅滞なく交付し、又は電磁的記録を遅滞なく提供する旨を表示するときは、省令で定めるところにより一部を表示しないことができる |
| 12条 | 誇大広告等の禁止。著しく事実に相違する表示、実際より著しく優良・有利と誤認させる表示（撤回・解除に関する事項を含む） |
| 12条の3〜12条の5 | 承諾をしていない者への電子メール広告・ファクシミリ広告の提供禁止等。**メール配信の同意は本スキルの対象外** |
| 12条の6 | 特定申込み（書面の申込み、インターネットの申込み画面）を受けるとき、その書面・画面に、1項1号 商品・役務の分量、2号 11条1〜5号の事項 を表示する義務。2項 申込みとなることについて誤認させる表示、1項の事項について誤認させる表示の禁止 |
| 13条の2 | 申込みの撤回・解除を妨げるための不実の告知の禁止 |
| 14条 | 主務大臣の指示。1項2号 顧客の意に反して申込みをさせようとする行為（規則42条1項: 申込み内容を、申込みとなる操作の際に容易に確認・訂正できるようにしていないこと） |
| 15条の3 | 通信販売における契約の解除等。商品・特定権利は引渡し・移転を受けた日から8日を経過するまで申込みの撤回・解除ができる。ただし、広告に撤回等についての特約を表示していた場合（電子消費者契約などは、広告に加えて省令で定める方法でも表示）は特約による。引取り・返還の費用は購入者の負担 |
| 15条の4 | 特定申込みの意思表示の取消し。12条の6の不実表示・不表示・誤認させる表示で誤認し申込みをしたときは取り消せる |
| 26条 | 適用除外。2027-07-22 施行予定の改正（金融商品取引法・資金決済法の一部改正）で文言が変わる予定。通販の表示事項（11条・12条の6・15条の3）の文言は、確認した2026-10-23時点の予定版でも変わらない |

## 規則（通信販売の節）

| 条 | 内容（要約） |
|---|---|
| 23条 | 法11条6号の事項。1号 氏名又は名称、住所、電話番号。2号 法人でインターネットなど電子情報処理組織で広告するときは、代表者又は通信販売業務の責任者の氏名。3号 外国法人・外国に住所を有する個人で国内に事務所等があるときはその所在場所と電話番号。4号 販売価格・送料以外の負担金の内容と額。5号 引き渡された商品が種類又は品質に関して契約の内容に適合しない場合の販売業者の責任についての定めがあるときはその内容。6号 プログラム記録物の販売、映画・音楽等を鑑賞させる役務、プログラムをファイルに記録させる役務のときは、利用に必要な電子計算機の仕様・性能その他の条件。7号 2回以上継続して契約する必要があるときは、その旨と金額、契約期間その他の販売条件。8号 販売数量の制限その他の特別の販売条件。9号 一部省略して書面・電磁的記録の請求に費用がかかるときはその額。10号 通信販売電子メール広告をするときは事業者のメールアドレス |
| 24条 | 表示方法。1号 送料は金額で。2号 引渡時期・提供時期は期間又は期限で。3号 撤回・解除に関する事項（返品特約を含む）は、顧客にとって見やすい箇所で明瞭に判読できるように、その他容易に認識できるように |
| 25条 | 11条ただし書による省略の範囲。負担金を全部表示しない場合と全部表示する場合で省略できる事項が違う。**返品の可否・条件・費用負担、23条6〜10号の事項は省略できない。** 契約不適合責任を負わない旨などの例外あり（原文の但し書を読む）。3項 インターネットでは、事項を電磁的方法で提供する旨の表示でも一部を表示しないことができる（技術的基準は4項） |
| 26条 | 12条の対象となる事項（性能・内容・関与・原産地、11条各号の事項） |
| 42条 | 14条1項2号の行為（申込み内容の確認・訂正）、メール広告の承諾の取り方 |
| 44条 | 15条の3第1項ただし書の方法。申込みとなる操作を行うための表示（最終確認画面）で、見やすい箇所に明瞭に判読できるように、容易に認識できるように表示 |

# デジタル商品・サブスク・最終確認画面

確認日: 2026-10-23。90日を過ぎたら公式を読み直す。条文の要約は `articles.md`。

出典:
- 別添9 通信販売の申込み段階における表示についてのガイドライン（令和6年11月19日版） https://www.caa.go.jp/policies/policy/consumer_transaction/specified_commercial_transactions/assets/consumer_transaction_cms101_2401119_03.pdf
- 別添7 通信販売における返品特約の表示についてのガイドライン https://www.caa.go.jp/policies/policy/consumer_transaction/specified_commercial_transactions/assets/consumer_transaction_cms101_230421_7.pdf
- 通達 https://www.caa.go.jp/policies/policy/consumer_transaction/specified_commercial_transactions/assets/consumer_transaction_cms101_2401119_01.pdf
- 通信販売広告Q&A https://www.no-trouble.caa.go.jp/qa/advertising.html

## 1. 最終確認画面（法12条の6）

- 「最終確認画面」は、申込みボタンなどを押すと契約の申込みが完了する画面。表題の有無や形式は問わない。画面遷移なしでスクロールするページなら、注文内容の確認に当たる部分。決済情報の入力だけが別画面に移る仕様なら、その前の申込み内容の確認画面が最終確認画面（別添9の脚注）
- 表記ページ（法11条の広告）に書いただけでは、最終確認画面の義務を果たしたことにならない。ただし、最終確認画面に参照の対象となる事項と参照先を明示し、リンク先に明確に書いてあれば、リンク先の記載を含めて表示と見る（別添9）
- 表示事項（法12条の6第1項）
  1. 分量: 数量、回数、期間。定期購入は各回の数量と引渡し回数（総分量が分かるように）。サブスクは役務の提供期間や、期間内に使える回数があればその内容
  2. 販売価格（複数商品は支払総額も）、送料は実際に払う額。定期購入は各回の代金と支払総額。無期限なら「目安」であることを明確にして1年分などの総額を示すことが望ましい
  3. 支払の時期と方法（定期購入は各回の時期）
  4. 引渡時期・提供時期（定期購入は各回の時期）
  5. 申込期間の定めがあるときはその旨と内容
  6. 撤回・解除に関する事項（返品特約を含む）。定期購入で解約の申出に期限があればその期限、違約金等があればその内容
- 表示の禁止（法12条の6第2項、取消しは法15条の4）
  - 押すと有償の申込みになることを分かりにくくする表示。「注文内容の確認」の画面に「申込みを確定する」ボタンがあれば一般に問題とならないが、「送信する」「次へ」だけで他に申込みと分かる表示が無いと誤認のおそれがある（別添9）
  - 1項の事項について誤認させる表示。例: 定期購入なのに、消費者が操作しない限り定期購入として申し込む設定を、商品欄に特段の記載なく置く。5か月分の契約で1か月分の分量だけ表示する

## 2. 継続課金（定期購入・サブスク）

- 広告（法11条）: 2回以上継続して契約する必要があるときは、その旨と金額、契約期間その他の販売条件（規則23条7号）。省略不可（規則25条）
- 期間の定めがない契約（消費者庁Q&A 21）: 当初から無期限なら、支払総額が決まらないので半年分・1年分などの目安を示し、目安にすぎないこと、解約通知がない限り続く無期限契約であることを書く。有期契約が自動更新されるなら、2回以上の契約が必要な旨、金額、契約期間などを示し、最終確認画面で2回目以降の目安を初回と分けて示すことが望ましい
- 無料・割引期間から有料・通常価格へ自動で移る場合は、移る時期と金額が分かるようにあらかじめ表示（別添9）
- 解約（法11条5号、別添9、通達）
  - 方法、期限、違約金などの不利益をそのまま書く
  - 方法を限定するとき（電話のみ、特定の時間帯のみ、電話の後にメッセージアプリの操作が要る、追加の個人情報が要る、申込み時の手段で解約できない）は、リンク先に任せず、広告と最終確認画面にも明確に書く
  - 電話で受けるなら、確実につながる番号を載せ、解約用の番号だと分かるように別に表示（法11条の電話番号と同じ番号でも）。かけてもつながらない、折り返しが無い運用は、不実の表示に当たるおそれがある（別添9、通達）
  - 制限を表示しても、制限が民事上有効になるとは限らない。不当に消費者の権利を制限する条項は消費者契約法等で無効となり得る
- 「いつでも解約できます」と書くなら、実態と一致させる（法12条・13条の2。解約を妨げるための不実の告知の禁止）

## 3. デジタル商品の返品・返金

- 通達の整理: 法15条の3は「返品が観念できない役務の通信販売」を対象としない
- 規則23条6号は、プログラムを記録した物の販売、映画・音楽・写真などを鑑賞させる役務、プログラムをファイルに記録させる役務を並べて、動作環境の表示を求めている。ダウンロード型を商品とみるか役務とみるかは、確認した一次情報では断定できない。**結論を出さず要確認にする。**
- どちらの整理でも、法11条5号は「撤回又は解除に関する事項」の表示を求める。役務提供契約では、1回の提供なら撤回の可否とその方法、複数回・一定期間なら契約途中の解約の方法等を分かりやすく表示（通達）
- 返品・返金を認めない場合は、その旨を広告と最終確認画面に書く（`SKILL.md` §6）。ダウンロード後は返金不可とするなら、いつの時点からか（購入直後か、ダウンロード開始時か）を具体的に
- 不具合（ファイルが開けない、説明と違う）に対する対応は、返品特約とは別に、契約不適合の責任として整理する。免責・制限の特約をするなら規則23条5号に基づく表示が要る（返品特約と区別して書く）

### 表示例（書き方の例。数値や条件は事実に置き換える）

- 返品特約を置く場合: 「返品・返金について: デジタルコンテンツは、ご購入手続の完了後の返品・返金に応じません。ただし、ファイルが開けない等、商品に不具合がある場合は、【要入力: 連絡先】へご連絡ください。」
- 区別して書く: 「商品に欠陥がない場合の返品はお受けしません。商品に欠陥がある場合は【要入力: 対応内容】。」
- 提供時期: 「ご決済の完了後、直ちにダウンロードできます。」
- 継続課金: 「月額【要入力】円（税込）。初回は【要入力】日間無料で、期間終了後は自動的に月額【要入力】円が課金されます。解約しない限り毎月更新されます。解約は【要入力: 方法】で、【要入力: 期限】までに行ってください。違約金は【要入力: 有無】。」

# 氏名・住所・電話番号の省略と非公開

確認日: 2026-10-23。90日を過ぎたら公式を読み直す。

出典:
- 法11条ただし書・規則25条 https://laws.e-gov.go.jp/law/351AC0000000057 ／ https://laws.e-gov.go.jp/law/351M50000400089
- 消費者庁 特定商取引法ガイド 通信販売（表示事項の省略） https://www.no-trouble.caa.go.jp/what/mailorder/
- 通信販売広告Q&A（15〜20） https://www.no-trouble.caa.go.jp/qa/advertising.html
- 通達（法11条ただし書の解釈） https://www.caa.go.jp/policies/policy/consumer_transaction/specified_commercial_transactions/assets/consumer_transaction_cms101_2401119_01.pdf

## 原則

- 通信販売の広告には、事業者の氏名（名称）・住所・電話番号を表示する（法11条6号・規則23条1号）
- 個人事業者も氏名が必要。屋号・通称・サイト名だけは不可。個人は戸籍上の氏名、法人は登記上の名称
- 法人がインターネットで広告するときは、代表者又は通信販売業務の責任者の氏名も（規則23条2号）。責任者は代表権が無くてよい
- 住所は現に活動している場所。私書箱は住所にならない。電話番号は確実に連絡が取れる番号で、営業していない時間は留守番電話等でよい

## 省略できる場合（法11条ただし書・規則25条）

次の2つを満たすとき、事項の一部を表示しないことができる。氏名・住所・電話番号、法人の代表者名・責任者名は省略できる事項に含まれる（消費者庁の整理）。

1. 広告に「請求により、これらの事項を記載した書面を遅滞なく交付し、又は電磁的記録を遅滞なく提供する」旨を表示する。文言は問わない。通達は「請求あり次第カタログ送付」でもよいとするが、①事項を載せた書面・電磁的記録であること、②請求に応じて遅滞なく送ることが分かる必要がある
2. 実際に請求があったとき、遅滞なく、省略した全事項を提供できる措置を講じている。「遅滞なく」は、申込みの意思決定に先立って十分な時間的余裕をもって提供されること。インターネット・オークションのように申込み期間が短い取引では困難と通達が述べる

省略できない事項（規則25条）: 返品の可否・条件・費用負担、23条6〜10号（動作環境、継続契約の条件、数量制限等の特別条件、請求に費用がかかる場合の額、メール広告のメールアドレス）。申込期間（法11条4号）、継続契約の条件も省略できない（消費者庁ガイド）。

## 非公開にしたい、と言われたとき

- 「請求がなければ公開しない」運用は、上の2つを満たして初めて成り立つ。省略は匿名販売を認めるものではなく、請求があれば開示する
- 事前に決めておくこと: 請求の受け口（メールアドレス、フォームなど。電話番号を省略するなら電話以外の受け口が要る）、返信の期限（申込みの意思決定に先立つ余裕を持てるか）、開示する情報（氏名・住所・電話番号・責任者名）、請求者の本人確認をするか（確認の要否は事実と運用による。要確認）
- プラットフォーム・バーチャルオフィスの住所・電話番号で代える個人事業者（消費者庁Q&A 18）: 取引がそのプラットフォーム上で行われること、連絡先として機能することの合意があること、事業者自身が現住所と本人名義の電話番号を把握し確実に連絡できることが要件として挙がっている。どれかの事業者が不誠実で連絡が取れないと、表示義務を果たしたことにならない。**要件を満たすかは事実を聞いて確認し、断定しない**
- 自宅住所に不安があるときに考えられる選択肢（一次情報が推奨するものではない。整理のための例）: 省略の要件を整える、Q&A 18 の要件を満たす形でバーチャルオフィス等を使う、必要な情報を開示して運用する。どれが適するかは事業の実態で変わる
- 電話番号の代わりにメールやフォームだけで足りるかは、確認した一次情報に代替を認める記述が無い。要確認とし、省略の枠組み（請求により遅滞なく開示）で整えられるかを検討する
- 他人の住所・名義の電話番号を、本人の合意や実態なしに載せる案は出さない

# 特商法表記のひな形（下書き用・通信販売）

確認日: 2026-10-23。条番号は `references/articles.md`。

使い方:
- 空欄は `【要入力】` と書く。事業者から聞いた事実だけを入れ、聞いていない事実（住所、電話番号、価格、送料、期間、返品条件）は入れない。ある節の事実が無いと分かったら、その節を消さず「【要確認】該当するかを確認」と残す
- 事実を確認したうえで「ありません」と書けるときだけ、そう書く
- 見出しの括弧内の条文は下書きの注。公開版では消す
- 下書きで、法的な適合を保証しない。ひな形に整えたうえで、最終確認画面（法12条の6）にも同じ事項を表示するか、明確に参照させる
- 住所・電話番号を省略する形（法11条ただし書）にするときは `references/omission.md` の2要件を満たす体制ができてから使う

## ひな形（デジタルコンテンツ・サブスクを想定）

```
特定商取引法に基づく表記

販売事業者（法11条6号・規則23条1号）
  氏名または名称: 【要入力: 個人は戸籍上の氏名、法人は登記上の名称】
  運営責任者（法人の場合・規則23条2号）: 【要入力】
  所在地: 【要入力: 実際に活動している場所】
  電話番号: 【要入力: 連絡のつく番号。受付時間: 【要入力】】
  メールアドレス: 【要入力】

  商品代金以外の必要料金: 【要入力: 送料、決済手数料、通信料など。無ければ「ありません」（事実を確認のうえ）】

お支払方法・時期（法11条2号）
  お支払方法: 【要入力】
  お支払時期: 【要入力: 例として、ご注文時 / 毎月の更新日 など実際の時期】

商品の引渡時期・提供時期（法11条3号・規則24条2号）
  【要入力: 期間または期限で。例として「ご決済の完了後、直ちにご利用いただけます」など実際の時期】

動作環境（規則23条6号）
  【要入力: 利用に必要なOS、ブラウザ、アプリなど】

申込みの期間（法11条4号）

継続して契約する場合の条件（規則23条7号）
  【要確認: 継続課金が無ければこの節は不要。ある場合は、金額、契約期間、更新、無料期間から有料に移る時期と金額】

返品・キャンセル・解約（法11条5号・規則24条3号・法15条の3）
  商品に欠陥がない場合の返品・返金: 【要入力: 可否、期間などの条件、返品費用の負担】
  商品に欠陥がある場合: 【要入力: 対応。免責・制限の特約をする場合はその内容（規則23条5号）】
  継続課金の解約: 【要入力: 方法、期限、違約金の有無、受付時間・連絡先】

その他の特別な販売条件（規則23条8号）
  【要確認: 個数制限、条件付き特典などがあれば】
```

def read_text(path):
    try:
        if path == "-":
            return sys.stdin.read()
        with open(path, encoding="utf-8") as f:
            return f.read()
    except (OSError, UnicodeDecodeError) as e:
        sys.stderr.write("読み込みに失敗: %s (%s)\n次の手: UTF-8 のテキスト（.txt か .md）で保存し直して、パスを確かめてください。"
                         "Word や PDF、画面のスクリーンショットは本文をコピーしてテキストにします。\n" % (path, e))
        sys.exit(3)


def scan(text):
    items = []
    for cid, name, article, patterns, conditional in ITEMS:
        found = all(re.search(p, text) for p in patterns)
        items.append({"id": cid, "item": name, "article": article,
                      "keyword_found": found, "conditional": conditional})
    leftovers = []
    for pat, label in LEFTOVERS:
        hits = re.findall(pat, text)
        if hits:
            ex = [m.group(0) for m in re.finditer(pat, text)]
            leftovers.append({"label": label, "count": len(ex), "examples": sorted(set(ex))[:3]})
    flags = []
    for pat, label, cid, ref in FLAGS:
        ms = [m.group(0) for m in re.finditer(pat, text)]
        if ms:
            flags.append({"id": cid, "label": label, "count": len(ms),
                          "examples": sorted(set(ms))[:2], "see": "references/" + ref})
    return items, leftovers, flags


def main(argv):
    ap = argparse.ArgumentParser(
        description="特商法表記（通信販売）の項目をキーワードで一次スクリーニングする（法適合の判断はしない）")
    ap.add_argument("path", help="表記本文のテキストファイル。標準入力は -")
    ap.add_argument("--json", action="store_true", help="JSON で出力する")
    ap.add_argument("--strict", action="store_true",
                    help="未検出（該当する場合のみの項目を除く）・取り残し・要注意の記載があれば終了コード1")
    try:
        args = ap.parse_args(argv)
    except SystemExit as e:
        sys.exit(2 if e.code not in (0, None) else 0)

    text = read_text(args.path)
    if not text.strip():
        sys.stderr.write("本文が空です。次の手: 特商法表記の本文を貼ったファイルを渡してください。\n")
        sys.exit(2)

    items, leftovers, flags = scan(text)
    missing = [i for i in items if not i["keyword_found"] and not i["conditional"]]

    if args.json:
        print(json.dumps({"items": items, "leftovers": leftovers, "flags": flags},
                         ensure_ascii=False, indent=2))
    else:
        print("| ID | 項目 | 条文 | キーワード |")
        print("|---|---|---|---|")
        for i in items:
            if i["keyword_found"]:
                mark = "検出"
            elif i["conditional"]:
                mark = "未検出（該当する場合のみ。事実を要確認）"
            else:
                mark = "未検出"
            print("| %s | %s | %s | %s |" % (i["id"], i["item"], i["article"], mark))
        print()
        if flags:
            print("要注意の記載:")
            for f in flags:
                print("- [%s] %s（%d件。例: %s。%s）" % (f["id"], f["label"], f["count"], " / ".join(f["examples"]), f["see"]))
        else:
            print("要注意の記載: なし")
        print()
        if leftovers:
            print("取り残し:")
            for l in leftovers:
                print("- %s（%d件。例: %s）" % (l["label"], l["count"], " / ".join(l["examples"])))
        else:
            print("取り残し: なし")
        print()
        print("注: 「検出」は言葉があるだけで、内容の適否は判断していない。references/checklist.md で確かめること。"
              "最終確認画面（法12条の6）は表記の本文だけでは見えないので、画面の文言を別に確かめる。")

    if args.strict and (missing or leftovers or flags):
        sys.exit(1)
    sys.exit(0)
