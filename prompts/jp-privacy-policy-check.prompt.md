# 日本のプライバシーポリシー点検

目的: Web サービス・アプリのプライバシーポリシーを、個人情報保護法（以下「法」）と電気通信事業法の外部送信規律に照らして点検し、足りない項目を根拠条文つきで指摘する。作成の下書きも作る。
入力: ポリシー本文（点検のとき）と、事業の実態の聞き取り（取得するデータ・目的・渡す先・使うツール）。
出力: 「項目 / 該当条文 / 現状の記載 / 指摘 / 直し方」の表と、末尾の「要確認」一覧。ひな形のときは `【要入力】` つきの下書き。
法的な結論は断定しない。根拠条文と、記載が見当たらない箇所を示すところまでが役目。

## 1. 条文の確認日（先に読む）

条文と制度は `references/` に確認日つきで置いてある。**確認日（2026-10-21）から90日を過ぎたら、公式を読み直してから使う。** 公式の入口:

- 個人情報保護委員会 法令・ガイドライン https://www.ppc.go.jp/personalinfo/legal/
- e-Gov 法令検索（個人情報の保護に関する法律） https://laws.e-gov.go.jp/law/415AC0000000057
- 総務省 外部送信規律 https://www.soumu.go.jp/main_sosiki/joho_tsusin/d_syohi/gaibusoushin_kiritsu.html

令和8年に法の改正が公布されたが、**主要部分は未施行**（施行日は要確認）。現行の義務として指摘するのは施行済みの条文だけにし、改正は「予定」として分ける（`references/appi-articles.md`）。

## 2. 最初に聞くこと（1回にまとめて）

素材に無いものだけ聞く。聞けない場合は、仮置きせず「要確認」に回す。

1. 運営者: 名称、住所、代表者（個人事業主は氏名）
2. 取得するデータ: 登録情報、問い合わせ、決済、アクセスログ、位置情報、Cookie、端末 ID。要配慮個人情報（病歴・信条など）を扱うか
3. 何のために使うか（サービスごと・データごと）
4. 誰に渡すか: 配送・決済・保守・メール配信・サポートなど外部の事業者、グループ会社、広告・解析事業者。渡す先が**自社の目的で使うか**（委託か第三者提供かの分かれ目）
5. 外国: サーバー、SaaS、委託先の所在国
6. Cookie・タグ・SDK: 入れているツール名、同意バナーの有無
7. 本人からの請求の受け付け: 窓口、本人確認、手数料、認定個人情報保護団体への加入
8. 子ども（16歳未満）や顔特徴データを扱うか（改正予定への影響を見る）

## 3. 点検モード

1. ポリシー本文を読む。文字にできるなら `python3 scripts/pp_scan.py <本文のファイル>` を実行し、キーワードの有無と取り残しの記号を一覧にする（実行できない環境では `references/checklist.md` を見ながら手で確かめる）。**スクリプトの「検出」は言葉があるだけで、適否の判断ではない。**
2. `references/checklist.md` の C01〜C20 を順に当てる。条文の中身は `references/appi-articles.md`、Cookie・タグは `references/external-transmission.md`。
3. 表で返す。1行は1項目。

```
| 項目 | 該当条文 | 現状の記載 | 指摘 | 直し方 |
|---|---|---|---|---|
| 利用目的の特定 | 法17条1項 | 「サービス向上のため」 | 抽象的で、何にデータを使うか本人が想定しにくい可能性があります | データ種別ごとに「会員登録情報を、本人確認と新機能のお知らせに利用」のように書く |
```

- 「現状の記載」は本文の引用か、「記載が見当たりません」。創作しない
- 指摘は「〜の可能性があります」「記載が見当たりません」「事実を確認のうえ判断してください」。「違法です」「違反しています」と書かない
- 重さは「要対応の可能性／要確認／推奨」で分ける。法が定める公表事項（法32条1項）の欠落は上に置く
- 引用された条番号が現行と合っているかも見る（旧い条番号、6か月要件など。`references/appi-articles.md` の「現行と食い違いやすい点」）

## 4. 委託・第三者提供・共同利用の書き分け

- 配送・決済代行・保守など、**自社の利用目的の達成に必要な範囲で任せる**もの → 委託（法27条5項1号。法25条で委託先を監督）。委託先は委託された範囲でしか使えない
- 渡した先が**自社の目的で使う**（自社の広告・分析・名簿に使うなど） → 委託ではなく第三者提供（法27条1項。本人の同意が基本）の可能性。事実を聞いて「要確認」にする
- グループ会社などで決まった範囲で共有 → 共同利用（法27条5項3号。5事項を事前に通知か容易に知り得る状態に）
- 外国の提供先は、上のどれでも**法28条を別に確認**する（`references/appi-articles.md`、外国にある第三者への提供編）

## 5. Cookie・解析・広告タグ

- 法の側: Cookie などで集めた閲覧履歴は「個人関連情報」の例。取得・利用目的の特定（17条・21条）と、第三者に渡す場合の整理（27条・31条）を見る。提供先が個人データとして取得するかは事実次第なので「要確認」
- 電気通信事業法の側: 外部送信規律は**事業の種類で対象が決まる**。総務省は、自社商品のオンライン販売、企業のホームページ、個人ブログは電気通信事業に該当せず対象外としている。SNS、オンラインショッピングモール、検索、ニュースなど各種情報のオンライン提供は対象になり得る。**自社が対象かは断定せず**、サービスの実態を聞き、総務省の FAQ で確認するよう案内する
- 対象外でも、外部に情報を送るツールを使っているなら、ツール・送信先・情報・目的を示すのが望ましい（法的義務とは書かない）
- Google Analytics などの個別ツールの取得項目・データ共有は設定で変わる。一般論で埋めず、提供事業者の公式ヘルプを確認する欄にする

## 6. ひな形モード

`references/template.md` をもとに、聞き取った事実だけで下書きを作る。

- 空欄は `【要入力】`（＜＞や○○にしない）。聞いていない事実は入れない
- 事実が無いと確認できていない節は消さず `【要確認】` を残す
- 最後に「事実を確認し、公開前に専門家の確認を受けることを勧める」と一言添える
- 下書きにも `python3 scripts/pp_scan.py <ファイル>` で取り残しを確認できる

## 7. 返し方

1. 点検表（または下書き）
2. 改正予定で注意する点（該当するときだけ）
3. 要確認の一覧（項目: 理由）
4. 根拠の確認日と、最新は公式で確認する旨（URL）

## 8. 対象外

個別の法的助言（訴訟リスク、制裁の見通しなど）、GDPR・CCPA など日本以外の法域、利用規約・特定商取引法表記の作成、社内の個人情報取扱規程、Cookie バナーの実装。依頼されたら対象外と伝え、必要なら専門家への相談を勧める。

| 27条1項 | 個人データの第三者提供はあらかじめ本人の同意（例外は各号） | 提供先、提供する項目、目的 |
| 27条2項 | オプトアウト（本人の求めで提供を停止する、事項を本人に通知か容易に知り得る状態に置き、個人情報保護委員会に届出）。要配慮個人情報などは対象外 | 使うなら事項の公表が要る。届出の有無を要確認 |
| 27条5項1号 | 利用目的の達成に必要な範囲で取扱いを**委託**する場合の提供先は「第三者」に該当しない（委託された業務の範囲内でのみ） | 委託と第三者提供の書き分け。提供先が自社の目的で使うなら委託ではない可能性 |
| 27条5項2号 | 事業承継に伴う提供も第三者に該当しない | 合併・事業譲渡の記載 |
| 27条5項3号・6項 | **共同利用**: その旨、共同して利用する項目、共同利用者の範囲、利用目的、管理責任者の氏名または名称・住所・代表者名を、あらかじめ本人に通知か容易に知り得る状態に置く。責任者の変更は遅滞なく、利用目的・責任者の変更は事前に | 5事項が全部あるか |

## 現行と食い違いやすい点

- 引用された条番号が古い: 現行で23条は**安全管理措置**、25条は**委託先の監督**、27条が**第三者提供**、32条が**保有個人データの公表等**、33条が**開示**、40条が**苦情処理**。「第23条に基づき第三者提供」「第25条に基づき開示」と書いてあれば旧番号の可能性が高い。現行の番号に直すよう指摘する
- 「保有個人データ」は、令5条（令和8年6月14日時点）で除外されるのは存否が明らかになると本人・第三者の生命等に危害が及ぶ、違法・不当な行為を助長する、国の安全が害される、公共の安全と秩序の維持に支障が及ぶ、の4類型で、**「6か月以内に消去するもの」は入っていない**。旧来のひな形にある「6か月以内に消去する個人データは保有個人データに含めない」は現行に合わないので指摘する
- 規則7条の漏えい報告対象に「本人の数が1,000人を超える」が入っている（2026-10-21 時点のガイドライン引用）

## 未施行の改正（令和8年改正）

# 電気通信事業法の外部送信規律（Cookie・タグ・SDK の通知・公表）

確認日: 2026-10-21（90日後の 2027-01-19 を過ぎたら公式を読み直す）

## 出典

- 総務省「外部送信規律」 https://www.soumu.go.jp/main_sosiki/joho_tsusin/d_syohi/gaibusoushin_kiritsu.html （2026-10-21 確認）
- 総務省「外部送信規律FAQ」 https://www.soumu.go.jp/main_sosiki/joho_tsusin/d_syohi/gaibusoushin_kiritsu_00002.html （2026-10-21 確認）
- 総務省「法令・ガイドライン・パンフレット」 https://www.soumu.go.jp/main_sosiki/joho_tsusin/d_syohi/gaibusoushin_kiritsu_00001.html （2026-10-21 確認）。法は電気通信事業法（昭和59年法律第86号）第27条の12、規則は電気通信事業法施行規則（昭和60年郵政省令第25号）第22条の2の27〜第22条の2の31、ガイドラインは「電気通信事業における個人情報等の保護に関するガイドライン」（令和4年個人情報保護委員会・総務省告示第4号）とその解説第7章
- 参考（案・確定前）: 総務省 利用者情報ワーキンググループ 第2次報告書（案）（令和8年7月6日）。通知・公表の雛形、対象外のウェブサイトにも準じた対応が望ましいとする方向 https://www.soumu.go.jp/main_content/001081002.pdf （2026-10-21 確認。**案**なので確定版を総務省のページで確認する）
- e-Gov 法令検索の本文は 2026-10-21 時点でメンテナンス中のため取得できなかった。条の中身は総務省の解説ページ・FAQ で確認した範囲だけを書く

施行は 2023年6月16日（総務省の解説ページに記載）。

## 何を求める規律か

電気通信事業を営む者（ウェブサイト運営者、アプリ提供者など）が、利用者の端末に**外部送信を指示するプログラム等**を送るとき、あらかじめ、次の事項を**通知するか、利用者が容易に知り得る状態に置く（公表）**。同意の取得、オプトアウト措置のいずれかでもよい。

通知・公表する事項（総務省の解説ページ）:

1. 送信されることとなる利用者に関する情報の内容
2. 1の情報を取り扱うこととなる者の氏名または名称
3. 1の情報の利用目的

方法: 日本語で記載、専門用語を使わない、平易な表現、拡大・縮小せずに適切な大きさで表示。ウェブサイトは外部送信のプログラムを送るページまたはそこから容易に到達できるページに表示、アプリは最初に表示される画面または容易に到達できる画面に表示。

## 誰に適用されるか（自社が対象かを必ず確認する）

- FAQ 問1-8: 電気通信事業を営む者のうち、「利用者の利益に及ぼす影響が少なくない電気通信役務」を提供するもの。電気通信事業を営んでいなければ、外部送信があっても対象外
- FAQ 問1-9（規則22条の2の27）: ブラウザやアプリで提供される、(1)メッセージ媒介等 (2)SNS・電子掲示板・動画共有・オンラインショッピングモール等 (3)オンライン検索 (4)ニュース配信・気象情報・動画配信・地図等の各種情報のオンライン提供
- 総務省の解説ページ: 自社商品のオンライン販売、企業等のホームページ運営・個人ブログは電気通信事業に該当せず対象外。FAQ 問1-12・1-13は、小売業者が自社サイトで商品を売るのは本来業務の手段にすぎず対象外と答えている。FAQ 問1-14は、複数の店舗・出品者の場を提供するオンラインショッピングモールは対象と答えている
- FAQ 問1-7: Cookie を使っていなくても、外部に情報を送信させるプログラムを送る行為全般が規律対象（対象事業者の場合）
- 判定が難しいとき（会員向けサービス、メディア＋EC 併営、コミュニティなど）は**断定せず**、サービスの実態（誰の何を媒介・提供しているか）を聞いたうえで「対象の可能性」「総務省の電気通信事業参入マニュアル・FAQ で要確認」とする

## 通知・公表が不要な情報（法27条の12第1号〜第4号、総務省の解説ページ・規則22条の2の30）

- サービス提供に必要な情報（OS・画面設定・言語設定・ブラウザ情報、入力した情報の保持、ユーザー認証、セキュリティ対策、ネットワーク管理に必要なもの）
- 自社が利用者に送付した識別符号（ファーストパーティ Cookie に保存された ID など）で自社に送信されるもの
- 利用者が同意している情報（チェックボックスに事前チェックを付ける等、能動的な同意といえない方法は不可）
- オプトアウト措置を講じ、利用者が適用を求めていない情報（オプトアウトの事実、停止するのは送信か利用か、申込み方法、サービス利用が制限される場合はその内容、情報の内容、取扱者名、利用目的を容易に知り得る状態に置く）

## 個人情報保護法との関係（混同しない）

- 外部送信規律は電気通信事業法の規律で、**対象でないサイトには適用されない**。一方、Cookie 等を使って個人情報を取得する・個人データを第三者に渡す・個人関連情報を渡す、は個人情報保護法（17条・21条・27条・31条など）の問題として別に残る
- 総務省の解説ページは外部送信規律の「通知・公表」をプライバシーポリシーと別立てにするかを指定していない。WG 報告書（案）はポリシー内に書く場合も見出しを立てるなど到達しやすくするのが望ましいとしている（案）
- 総務省の整理では、外部送信規律の対象外のサイトでも、規律の趣旨に鑑み外部送信の事実を分かりやすく示す自主的な取組が望ましい、という方向（WG 報告書（案））。これは法的義務ではなく**望ましい対応**として書く

## ポリシーに入れる記載の型（事実は事業者から聞く）

ツールごとに行を作る。ツール名・送信先事業者名・国名・送信される情報・利用目的の事実は事業者の設定によるので、**素材に無ければ【要入力】**。

| ツール・サービス | 送信先（事業者名・国） | 送信される情報 | 利用目的 | 停止の方法 |
|---|---|---|---|---|
| 【要入力】 | 【要入力】 | 【要入力】 | 【要入力】 | 【要入力】 |

Google Analytics、広告タグ、SNS ボタン、アプリの SDK などは、提供事業者・取得項目・データ共有の設定が事業者側の設定で変わるため、一般論で埋めず、提供事業者の公式ヘルプで確認するよう案内する。

11. 苦情・お問い合わせ窓口（法40条、32条1項4号・令10条）
窓口: 【要入力】

12. 本ポリシーの改定
重要な変更を行う場合は、【要入力: 掲載・通知の方法】によりお知らせします。

#!/usr/bin/env python3
"""プライバシーポリシー本文を読み、点検項目のキーワードが有るかを一覧にする（一次スクリーニング）。

使い方:
  python3 scripts/pp_scan.py policy.txt            # 表で出力
  python3 scripts/pp_scan.py policy.txt --json     # JSON で出力
  cat policy.txt | python3 scripts/pp_scan.py -    # 標準入力
  python3 scripts/pp_scan.py policy.txt --strict   # 未検出や未入力が残っていれば終了コード 1

できること: キーワードの有無、未入力の穴埋め記号の取り残し（【要入力】、＜＞、山括弧、○○、XXX）の検出。
できないこと: 記載内容が法に適合しているかの判断。「検出」は言葉があるという意味だけで、
中身が足りているかは人が references/checklist.md で確かめる。外部へ通信せず、ファイルも書かない。

終了コード: 0 正常 / 1 --strict で指摘あり / 2 引数エラー / 3 読み込み失敗
実行できない環境では: references/checklist.md の項目 C01〜C20 を、本文を読みながら手で確かめる。
Python 3.9 の標準ライブラリだけで動く。
"""
import argparse
import json
import re
import sys

# (ID, 項目, 条文, 検出パターン, 該当する場合のみ必要か)
ITEMS = [
    ("C01", "事業者の名称・住所・代表者", "法32条1項1号", [r"(住所|所在地)", r"代表"], False),
    ("C02", "取得する情報の項目・取得方法", "法20条1項・21条", [r"(取得|収集)する(個人)?情報|取得方法|取得する項目|収集方法"], False),
    ("C03", "利用目的", "法17条1項", [r"利用目的|以下の目的|次の目的|目的で(利用|使用)"], False),
    ("C04", "利用目的の変更", "法17条2項・21条3項", [r"利用目的.{0,12}(変更|追加)"], False),
    ("C05", "要配慮個人情報", "法20条2項", [r"要配慮"], True),
    ("C06", "安全管理措置", "法23条・32条1項4号", [r"安全管理"], False),
    ("C07", "委託", "法25条・27条5項1号", [r"委託"], True),
    ("C08", "第三者提供", "法27条", [r"第三者(へ|に)?(の)?提供|第三者提供"], False),
    ("C09", "共同利用", "法27条5項3号", [r"共同(して)?利用"], True),
    ("C10", "外国にある第三者・外国保管", "法28条", [r"外国|海外|国外"], True),
    ("C11", "Cookie・アクセス解析・広告タグ・外部送信", "法31条・電気通信事業法27条の12", [r"Cookie|クッキー|アクセス解析|Google\s*Analytics|広告配信|タグ|外部送信|SDK|ピクセル"], True),
    ("C12", "保有個人データの公表事項（手続）", "法32条1項3号", [r"開示"], False),
    ("C13a", "訂正・利用停止等の請求", "法34条・35条", [r"訂正", r"利用停止|消去"], False),
    ("C13b", "手数料", "法32条1項3号・38条", [r"手数料|無料"], False),
    ("C13c", "本人確認・代理人", "法37条・令12条・13条", [r"本人確認|代理人"], False),
    ("C14", "苦情・問合せ窓口", "法40条・令10条2号", [r"窓口|苦情|お問い?合わせ"], False),
    ("C14b", "認定個人情報保護団体", "令10条3号", [r"認定個人情報保護団体"], True),
    ("C17", "制定日・改定日・改定手続", "法21条3項", [r"制定日|改定日|最終更新|施行日|改訂|改定"], False),
]

# 取り残しの穴埋め記号
LEFTOVERS = [
    (r"【要入力[^】]*】", "【要入力】が残っている"),
    (r"【要確認[^】]*】", "【要確認】が残っている"),
    (r"[＜<][^＞>\n]{1,30}[＞>]", "＜＞の穴埋めが残っている可能性"),
    (r"\u3008[^\u3009\n]{1,30}\u3009", "山括弧の穴埋めが残っている"),
    (r"○○|△△|□□|XXX|xxx", "○○・XXX などの仮の文字が残っている"),
]


def read_text(path):
    try:
        if path == "-":
            return sys.stdin.read()
        with open(path, encoding="utf-8") as f:
            return f.read()
    except (OSError, UnicodeDecodeError) as e:
        sys.stderr.write("読み込みに失敗: %s (%s)\n次の手: UTF-8 のテキスト（.txt か .md）で保存し直して、パスを確かめてください。"
                         "Word や PDF は本文をコピーしてテキストにします。\n" % (path, e))
        sys.exit(3)


def scan(text):
    items = []
    for cid, name, article, patterns, conditional in ITEMS:
        found = all(re.search(p, text) for p in patterns)
        items.append({
            "id": cid, "item": name, "article": article,
            "keyword_found": found, "conditional": conditional,
        })
    leftovers = []
    for pat, label in LEFTOVERS:
        hits = re.findall(pat, text)
        if hits:
            leftovers.append({"label": label, "count": len(hits), "examples": sorted(set(hits))[:3]})
    return items, leftovers


def main(argv):
    ap = argparse.ArgumentParser(description="プライバシーポリシーの項目をキーワードで一次スクリーニングする（法適合の判断はしない）")
    ap.add_argument("path", help="ポリシー本文のテキストファイル。標準入力は -")
    ap.add_argument("--json", action="store_true", help="JSON で出力する")
    ap.add_argument("--strict", action="store_true", help="未検出（該当する場合のみの項目を除く）や取り残しがあれば終了コード1")
    try:
        args = ap.parse_args(argv)
    except SystemExit as e:
        sys.exit(2 if e.code not in (0, None) else 0)

    text = read_text(args.path)
    if not text.strip():
        sys.stderr.write("本文が空です。次の手: ポリシー本文を貼ったファイルを渡してください。\n")
        sys.exit(2)

    items, leftovers = scan(text)
    missing = [i for i in items if not i["keyword_found"] and not i["conditional"]]

    if args.json:
        print(json.dumps({"items": items, "leftovers": leftovers}, ensure_ascii=False, indent=2))
    else:
        print("| ID | 項目 | 条文 | キーワード |")
        print("|---|---|---|---|")
        for i in items:
            if i["keyword_found"]:
                mark = "検出"
            elif i["conditional"]:
                mark = "未検出（該当する場合のみ。事実を要確認）"
            else:
                mark = "未検出"
            print("| %s | %s | %s | %s |" % (i["id"], i["item"], i["article"], mark))
        print()
        if leftovers:
            print("取り残し:")
            for l in leftovers:
                print("- %s（%d件。例: %s）" % (l["label"], l["count"], " / ".join(l["examples"])))
        else:
            print("取り残し: なし")
        print()
        print("注: 「検出」は言葉があるだけで、内容の適否は判断していない。references/checklist.md で確かめること。")

    if args.strict and (missing or leftovers):
        sys.exit(1)
    sys.exit(0)


if __name__ == "__main__":
    main(sys.argv[1:])
